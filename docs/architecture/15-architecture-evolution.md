# 架构演进准入

Updated: 2026-10-19

架构演进必须由可复核的证据驱动。路线图中的长期方向（多渲染后端、领域插件平台）是待验证假设，只有满足本页准入门槛才会进入实现与公共 API。

## 准入门槛

一个架构提案必须同时具备：

1. **问题证据**：来自真实消费端的缺陷、性能数据、兼容性失败或明确的能力缺口；仅有“更优雅”“更通用”的偏好不构成证据。
2. **量化目标**：基线指标与目标值，例如包体积、首屏耗时、Worker 内存、任务延迟、失败率或迁移成本。
3. **最小验证**：不改变稳定 API 的探针、实验性入口或独立分支原型，附可复现步骤与测量结果。
4. **替代方案与成本**：至少一个不改架构的替代方案，说明受影响包、公共导出、迁移周期与维护成本。
5. **回滚**：明确回滚到现状的路径。
6. **决策记录**：在本页登记结论（接受 / 推迟 / 拒绝）与证据链接；接受项同时更新路线图、兼容矩阵和迁移文档。

没有量化目标或无法回滚的提案不得进入稳定 API。

## 提案模板

```markdown
### <标题>

- 日期：YYYY-MM-DD
- 状态：proposed / accepted / deferred / rejected
- 问题证据：<issue / 消费端报告 / 基准数据链接>
- 基线：<当前指标与测量方法>
- 目标：<可验证的目标值>
- 方案：<最小变更与实验性入口>
- 替代方案：<不改架构的可行路径及未采用原因>
- 影响：<包 / 公共 API / 版本位 / 迁移成本>
- 回滚：<恢复路径>
- 结论与日期：<决策人 / 理由>
```

## 当前记录

### 多渲染后端

- 状态：deferred
- 问题证据：暂无真实消费端提出非 Cesium 引擎需求；现有 Engine 接缝足以隔离 Cesium 生命周期，但替换后端会改变场景、材质、数据源与拾取合同。
- 基线：2.0.0 的公共导出与 `CesiumEngine` 适配层；`arc3dlab/engine-cesium` 保持实验性。
- 准入条件：出现至少一个需要非 Cesium 渲染的消费端场景，并给出性能、能力或合规指标，且能证明现有 `Engine` 接缝无法通过适配层满足。
- 决策：继续维持 Cesium-first 与实验性适配子路径；不新增公共多后端 API。

### 共享全局 Worker 池

- 状态：deferred
- 问题证据：当前 `AnalysisJobHost` 按实例持有 Worker 槽位（最多 4 个），并支持空闲回收；尚无多实例内存或线程争用的实测数据。
- 准入条件：提供多应用实例下的内存、线程数与延迟基线，证明实例级池是瓶颈，且共享池不会破坏取消、销毁与错误隔离语义。
- 决策：保留实例级池；通过 `idleTimeoutMs` 与诊断计数观测，不以推测替代测量。

### 发布产物与消费端验证

- 状态：accepted（2.0.0 已实现）
- 问题证据：仅在工作区运行测试无法暴露 `files` 漏项、source map 泄漏、ESM-only 声明与 Worker 资产路径问题。
- 基线：`npm pack --dry-run` 清单、`test:pack` 安装 smoke、真实 Vite 消费者的生产构建与浏览器 Worker 往返。
- 结果：发布清单由 `scripts/publish-manifest.mjs` 与 pack/registry 检查共同约束；`test:consumer` 覆盖 tarball 安装、Worker 加载与降级路径。
- 回滚：保留 `test:pack` 作为最小门禁；消费端 smoke 可独立关闭而不影响发布包合同。

## 评审节奏

- 每次 minor 规划时复核 deferred 提案，证据不足则继续推迟。
- 每个 accepted 提案必须在下一个发布检查清单中列出验证结果。
- 移除或替换稳定 API 时同时检查弃用周期与迁移文档；不得以架构演进为由跳过 SemVer 规则。
